# Asset sources and provenance

Every image GOATerizer ships is recorded here: what it is, who made it, and
under what licence. `AGENTS.md` §11 requires this even where attribution is not
legally required.

Nothing is hotlinked at runtime. All art is stored under `public/assets/` and
served by this project.

---

## Rocky Ascent, and its three companions — placeholder art (CURRENT)

`scripts/generate-placeholder-art.mjs` generates all four scenarios from one
set of shared drawing functions in `scripts/lib/rocky-art.mjs`: a goat pose
cycle, a foothold, a destination cairn, a dust puff, a tick glint, and a
mountain backdrop. Rocky Ascent High, Rocky Descent and Rocky Descent High
reuse that same set rather than each getting distinct art, because their own
scenario files say to: each names `"Placeholder source families may be reused
from the normal version; final art can distinguish the high version later"`
(Rocky Descent's file states the same intent for reusing Rocky Ascent's
families). Only the background and dust carry a per-family RNG seed, so the
four are not byte-identical files while still reading as one consistent set;
re-running the generator reproduces every file byte for byte.

Every asset id below follows `<kind>_<scenario id>[_suffix]` — swap
`rocky_ascent` for `rocky_ascent_high`, `rocky_descent`, or
`rocky_descent_high` (and the directory for the matching
`public/assets/scenarios/<dir>/`) to get any companion's table.

### Why these, and not the sources the scenario file names

`docs/scenarios/rocky-ascent/rocky_ascent.scenario.json` names four third-party
CC0 packs as the intended placeholder sources (below). They are the right kind
of placeholder and remain the intended swap-in.

They are **not** what ships today. The environment this vertical slice was built
in cannot reach `itch.io` or `opengameart.org` — outbound requests to both are
refused by the network policy — so neither the files nor their licence pages
could be fetched and verified. `AGENTS.md` §11 requires verifying the source
page and the licence before reusing external art, and the implementation brief
allows substituting "another clearly license-safe placeholder with equivalent
purpose" when a named source is unavailable. Shipping unverified third-party art
was the one option not on the table.

checked from this environment.

### How to swap them in

1. Download from the source page and re-verify the licence.
2. Extract the single frames named above — the runtime treats every sprite as a
   **static billboard**, so strips and GIFs must be reduced to one frame each.
3. Save each as `public/assets/scenarios/<scenario dir>/<asset id>.png`,
   overwriting the generated placeholder — once per directory
   (`rocky-ascent/`, `rocky-ascent-high/`, `rocky-descent/`,
   `rocky-descent-high/`) you want to carry real art, using that directory's
   own asset ids.
4. Move that source's row from "intended" to a new shipped section of this file,
   with the licence you verified and the date you verified it.

No code change is needed: the asset ids and their slot bindings are scenario
data, and the runtime loads whatever is at those paths.

## Can Crushing — placeholder art (CURRENT)

The one `RepeatMinigame` scenario, and the only one outside the Rocky family. It
shares the generator and the discipline but none of the drawing functions: it is
a different class, a different theme and a different palette — beach at golden
hour rather than alpine dusk — so its shapes live in
`scripts/lib/crusher-art.mjs`.

Seven files for the seven slots the runtime binds. The ids are the canonical
ones from `GOATerizer_Scenario_Asset_Slot_Bindings.md` §3, so real art drops in
against the same names.

| `hero80_can_crushing_ready` | `…/hero80_can_crushing_ready.png` | `performerNeutral` |

| `fx_can_crushing_impact` | `…/fx_can_crushing_impact.png` | `impactEffects[0]` |

The catalogue also names `debrisEffects[]` and `streakEffects[]` for this
scenario. The runtime's `RepeatAssetBindings` does not bind them yet, so no file
is generated for either — an unbound slot with no art is honest; an unbound slot
with art nothing loads is clutter.

- **Author:** original work for this repository.
- **Licence:** CC0 / public domain. No third-party rights are involved.
- **Source:** generated by `scripts/generate-placeholder-art.mjs`
  (`scripts/lib/crusher-art.mjs` holds the editable drawing functions).

**Note on the prototype.** The timeline-actor draft draws the crusher, his cans
and his pile with canvas primitives in `src/ui/timeline/repeat-layer.ts` rather
than from these PNGs — the same choice, and the same reasoning, as the goat in
`actor-layer.ts`. The files exist because the scenario binds them and the strip
uses the background; when the actor layer stops being a prototype it should draw
these instead.

## Rules for any future asset

- Verify the source page and the licence before use; prefer CC0.
- Record source URL, author and licence here, even when attribution is not
  legally required.
- Store the file in this project; never hotlink at runtime.
- Do not introduce copyrighted commercial game assets as placeholders.
- Do not create many near-identical assets where a runtime transform or a
  duplicated instance produces the same result — one foothold sprite is
  instantiated up to thirty times per attempt, varied only by transform.
